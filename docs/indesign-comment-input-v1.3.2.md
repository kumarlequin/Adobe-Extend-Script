# InDesignコメント入力 v1.3.2 検証記録

確認日: 2026-11-25（日本時間）

## 不具合と原因

v1.3.1の「PDFコメント編集」で、Command+Returnを押しても「反映して閉じる」が実行されない（実機報告）。

- 主因（コードからの判断）: 入力欄自身へ `addEventListener("keydown", 処理, true)` で登録していた。第3引数 `true`（キャプチャ）は親要素でだけ呼ばれ、イベントの対象である入力欄自身では呼ばれない。
- 併せて、`event.metaKey` が `false` の場合に `keyboardState` を参照していなかった。
- v1.2.3にも同じ登録方法がある（元ファイルとして変更せず保持）。

## 改修内容

- 入力欄への登録からキャプチャ指定を外した。
- ダイアログにも確定用の登録を追加し、入力欄以外にフォーカスがある場合も確定できるようにした。改行は入力欄でだけ扱う。
- Command / Shiftは、イベントと `ScriptUI.environment.keyboardState` のどちらかが押下を示せば有効とした。Shift優先は維持した。
- Returnの判定へ `NumpadEnter` と `keyIdentifier` を追加した。
- 同じキー操作の二重通知で二重に保存しないよう、実行中と完了後300ミリ秒は再確定しない。
- 確定は既存ボタンの `onClick` を `notify` で呼ぶ（実機で動作しているIllustrator版と同じ方式）。検証・保存経路は変更していない。
- 「コメント編集」でも、表示時に入力欄へフォーカスを置く。

## 静的検査と模擬検証

- 先頭ディレクティブを除いた全文の構文検査（JavaScriptCore）: 合格。追加部分にES3以外の構文がないことを語の検索で確認した。ES3モードの構文解析器は使用していない。
- イベントの配信段階（キャプチャ・対象・バブル）を再現した模擬検証: 13,618件合格。v1.3.1は同じ模擬環境で確定0回となり、報告の症状と一致した。
- 二重通知、検証エラー後の再確定、例外後の復帰、無関係なキーを確認した。
- v1.3.1との差分は、キー処理、登録2か所、「コメント編集」の表示時フォーカス、定数1個、版番号のみ。

## 実機確認

2026-11-25、ユーザーがInDesignでCommand+Returnが効くことを確認した（確認した画面の内訳は未聴取）。
